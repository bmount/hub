## 2. Delete a repository, and purge an organization's git data

The hub needs both:
- to replace `mcc/agentfeed` and `mcc/pricebench`, which were imported with a stepwise-push workaround before the
  large-push fix, by deleting them and re-importing each with one ordinary push;
- to release the names of organizations deleted in the hub (`tenant.delete` keeps the name reserved until the git
  data is purged).

**What the hub needs, as an outcome:**
- **`repo.delete`.**
  - An admin deletes one repository; a confirmation must repeat its name.
  - Afterwards the repository is not listed, git requests to it answer not found, and creating the same name gives an
    empty repository.
  - All of its stored data is gone, including large objects in R2.
  - A delete interrupted midway can be retried to completion.
- **`tenant.purge`.**
  - An admin removes every repository of one tenant and the tenant's own registry state; a confirmation must repeat
    the tenant name.
  - Afterwards the tenant name is as if never used.
- **Reachable by the hub.** Today it calls `repo.create` at `https://ardi-pimwell.bvmount.workers.dev/t/<tenant>/api/<verb>`
  with Basic auth, where the password is a hub `pms_` token whose role maps to admin. The same path for these would be
  ideal.

**Reference only.** The hub session had started an implementation and stopped. It is saved outside Ardi as
`docs/requests/ardi-repo-delete-unfinished.patch` in the hub repo (1,183 lines; never committed, pushed or deployed). Use it or ignore it.
